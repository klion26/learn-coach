# 交互与可视化参考

原则：**没有任务的图不发**。每张图、每个页面都必须让学习者做一个动作：预测、选择、排序、修改、解释。

---

## 1. 选型表

| 学习目标 | 形态 | 学习者动作 |
| --- | --- | --- |
| 看全局结构、依赖关系 | 知识地图 / 层级树 / 依赖图 | 标出"最没把握的一块"、调整学习顺序 |
| 理解机制如何运转 | 分步动画 / 状态机 / 流程图 | 预测下一步状态，再单步验证 |
| 区分相似概念 | 并排对比表 / 双栏图 | 把新案例归入某一栏并说明依据 |
| 看清变量间关系 | 滑杆 + 实时图表 | 调参数并预测曲线走向 |
| 掌握流程/算法 | 单步执行表格（trace table） | 填下一行的值 |
| 掌握代码 | 可运行片段 | 先预测输出 → 运行 → 改坏一处 → 再预测 |
| 建立直觉 | 小模拟器（canvas/SVG） | 设定初始条件，观察并解释偏差 |
| 检查理解 | 自包含测验页 | 作答 + 看即时反馈 + 重做错题 |
| 组织自己的知识 | 空白骨架图 | 让学习者自己填节点 |

---

## 2. 标准教学序列（每张交互图都套这个）

```
1. 给情境（具体、最小）
2. 让他预测（写下或点选）
3. 让他操作/观察
4. 对比预测与结果 → 差异就是学习点
5. 让他解释差异（一句话）
6. 换一个条件重来（迁移）
```

第 2 步和第 5 步最容易被跳过，**不要跳**。

---

## 3. 交互模式清单

优先选能让学习者**动手改**的，而不是**点下一步看**的：

- **预测-验证**：先猜输出/状态，再揭晓。最便宜、最有效。
- **滑杆探索**：一个变量一个滑杆，实时反馈，让他找到临界点。
- **逐步执行（stepper）**：算法/协议/内存布局，支持前进后退，每步高亮变化处。
- **拖拽分类**：把案例卡片拖进概念桶，错放立即解释。
- **填空/补全代码**：留 1–3 个空，只考当前 chunk 的点。
- **找错（bug hunt）**：给出一个"看起来对"的版本，让他找出偏差。
- **路径选择**：给流程图上的分叉，让他选并承担后果，展示分支结果。
- **可点击地图**：点击节点展开一句话说明 + 一个自测题。
- **对比切换**：同一场景在两个方案间切换（A/B toggle），差异用高亮标出。

## 4. HTML 编写约束

生成在 `<learn-dir>/<slug>/artifacts/NN-名字.html`：

- **单文件自包含**：内联 CSS/JS，不引用 CDN、不加载外部字体/图片。离线可用。
- **纯原生**：vanilla JS + SVG/canvas，不引入框架（避免加载失败与体积）。
- **键盘可用**：`1-9` 选项、`Enter` 提交、`←/→` 步骤切换。
- **移动端可读**：`max-width: 760px` 居中，字号 ≥ 16px。
- **深浅色都行**：用 `prefers-color-scheme` 或中性的高对比配色。
- **即时反馈**：答对/答错立即着色 + 一句解释（错也要解释，不能只显示红叉）。
- **进度可见**：顶部显示 `3/6`。
- **无追踪**：不写 localStorage 之外的持久化（可选，用于重做错题）。
- 生成后直接给打开命令（macOS `open`，Linux `xdg-open`）：`open <learn-dir>/<slug>/artifacts/NN-xxx.html`。

聊天里的轻量可视化用 Markdown + Mermaid（`flowchart`、`sequenceDiagram`、`stateDiagram-v2`、`timeline`），但**复杂交互必须落到 HTML**——Mermaid 只能看，不能操作。

---

## 5. 常见退化（不要做）

- 一页几千字，配一张装饰图 —— 这是讲义，不是交互。
- 交互只是"点下一步" —— 没有预测和解释，等于动画片。
- 一个页面塞 5 个概念 —— 违反 3 元素上限。
- 用颜色做唯一区分手段（色盲不可用）。
- 把答案和解释同时显示 —— 先让他答，再揭晓。
- 默认"看懂了"就是学会了 —— 必须落到操作和测试。
