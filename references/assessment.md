# 评估参考：SOLO 分级 + 交叉验证

## 1. SOLO 五级与判定

| 层级 | 表现 | 可观察证据 | 典型题干 |
| --- | --- | --- | --- |
| Prestructural 前结构 | 用错概念、答非所问、只有结论无依据 | 提到关键词但关系错 | "X 是什么？"（答成 Y） |
| Unistructural 单点 | 抓住一个相关点 | 能说出定义/一个特征 | "X 的定义/唯一关键区别是什么？" |
| Multistructural 多点 | 列出多个点，但彼此孤立 | 能列举 3 条特征但不排序、不关联 | "列出 X 的四个组成部分/三种方法。" |
| Relational 关联 | 能解释关系、因果、比较、整合 | 能说"因为…所以…""两者差别来自…" | "为什么 A 会导致 B？X 和 Y 的本质区别是什么？" |
| Extended abstract 抽象扩展 | 能迁移到新情境、评价、生成、质疑前提 | 能把原理用到没见过的场景，或指出失效条件 | "在 Z 场景你会怎么做？这个方法的代价是什么？什么情况下它不成立？" |

**判定纪律**
- 出现术语但机制错 = 前结构，不是多点。
- 能列举不能比较 = 多点，不是关联。
- 能复述正确答案但换情境就崩 = 多点停在原地，不是抽象扩展。
- 目标层级由 Phase 0 决定，**不要默认要求抽象扩展**；目标是"能用"时，关联层 + 一次迁移通常足够。

**掌握门槛（默认）**
- 单点/多点题：全对。
- 关联题：至少 1 题通过，且理由完整（因果链没断）。
- 迁移题：能给出方案 + 说明依据，允许细节不完美。
- 无未解释的错误概念。

## 2. 交叉验证协议（Cross-Validation）

目的：区分"真懂"与"记住了答案"。对每道关键题，至少取 2 个维度；对 GATE 里最核心的那道题，取 3 个以上。

| 维度 | 做法 | 抓什么 |
| --- | --- | --- |
| V1 内容正确性 | 对/错 | 表层 |
| V2 理由（reasoning） | "用一句话说明为什么" | 蒙对、背答案 |
| V3 信心校准 | 答前给 0–100% 把握 | 自信地错（危险）、心虚地对（不稳） |
| V4 反例/边界探针 | "什么情况下这个结论不成立？""这个和 X 差在哪？" | 只有单例表征、过度泛化 |
| V5 迁移 | 换个情境/数据/语言问同一个原理 | 表面记忆 |
| V6 一致性 | 与之前答案、与 state.json 里记录的错误概念对照 | 知识碎片互相矛盾 |

**冲突处理**

| 现象 | 诊断 | 动作 |
| --- | --- | --- |
| 对但理由错 | 蒙对/错误模型 | 不通过；出示两者的区别，要求判断第二个类似案例 |
| 对但信心 < 40% | 未固化的正确直觉 | 通过但标记 `fragile`，下次复习优先 |
| 错但信心 > 80% | 错误概念（最危险） | 立即干预：展示冲突证据 → 要求他解释矛盾 → 重新出题 |
| 两题结论互相矛盾 | 未整合 | 停下新内容，出对比题，要求统一表述 |
| 只会用术语 | 表征单一 | 要求"不用术语讲给外行"，或用图/例子表达 |

**评分取最低维度**，不做平均。低分维度决定这一块的等级。

追问纪律：一次只追问**一个**维度，不要连问五个"为什么"。追问到能定位错误模型就停。

## 3. 每关题目结构（GATE 配方）

一次 3–6 题，覆盖：

1. `1 × Unistructural` —— 关键术语/判据（快速确认地基）
2. `1–2 × Multistructural` —— 列举/区分
3. `1 × Relational` —— 因果或对比（本关核心，必考）
4. `1 × Extended abstract` —— 迁移到新情境（可放宽）
5. `≥1 × 旧内容` —— 交错，来自前面的 chunk
6. `≥1 × 错误概念` —— 来自 `state.json.misconceptions`（若有）

题面要求：
- 情境化，不要"下列哪个是定义"这种纯背诵。
- 干扰项必须是**学习者可能真的会犯的错**，不是明显荒谬项。
- 每题一个考点。多个考点混在一起会污染诊断。
- **题干必须自洽**：凡是决定答案的前提都要写出来——变量后续是否被使用（决定 region 是否相交）、两个 place 是什么关系、目标码是哪一类。省略这些前提会让"正确答案"变成"出题人的默认假设"，学习者答对也会被判错。
- **出题前先自己算一遍**：region 区间、错误码、能否编译。算不清楚的题不要发。发出去的题如果错了，当场作废并说明，不要让学习者替坏题买单。

## 4. 反馈写法

结构固定三行：

```
判定：{通过 / 未通过 / 部分通过}（SOLO: {层级}）
对在哪：{具体到他的表述}
错在哪：{命名错误模型，而不是"不够准确"}
下一步：{一个可执行动作}
```

错误要**命名**（例如"你把'接口隔离'和'依赖倒置'混成了一个概念"），命名后学习者才能追踪。

## 5. 错题本与错误概念管理

`state.json` 的 `misconceptions` 每条：

```json
{
  "id": "m3",
  "claim": "学习者认为 RAII 能防止内存泄漏（实际只保证释放时机）",
  "evidence": "GATE2 Q3：说 'drop 一调用就不会泄漏'",
  "status": "open",
  "probe": "若析构前进程 abort 会怎样？",
  "resolvedAt": null
}
```

规则：
- 错误概念只有在**换情境重考通过 + 能说明为什么原来错了** 之后才能标 `resolved`。
- 每关至少抽考一条 `open` 错误概念。
- 复习时优先考错误概念，其次考 `fragile` 概念。

## 6. 长期能力画像

每完成一个 chunk，更新一句能力声明，用**行为动词**：

- ✅ "能在一段 Rust 代码里指出所有权转移发生的位置并说明为什么编译失败"
- ❌ "掌握了所有权"

INTEGRATE 阶段输出三栏：**现在能做 / 仍然薄弱 / 下一步建议**。这是学习者最需要的收尾产物。
